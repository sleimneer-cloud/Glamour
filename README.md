# 🌟 Glamour (글래머) - 초개인화 AI 문법 튜터 & 영작 보조 서비스

> "번역기(파파고)에만 의존하기엔 내 실력이 늘지 않고, 빈 종이에 직접 영작하기에는 막막한 2030을 위한 인터랙티브 영작 튜터"

## 1. 프로젝트 소개
**Glamour**는 '영작'이라는 구체적인 상황에서 사용자의 인지적 부담(백지 증후군)을 덜어주고, 능동적인 학습을 유도하는 MSA 기반 AI 서비스입니다. 
단순히 완성된 번역을 제공하는 기존 번역기와 달리, 파편화된 단어나 엉터리 입력(혹은 손글씨 OCR)을 기반으로 **'맞춤형 문장 조립 칩'**을 생성해주며 동적 UI를 통한 어순 학습을 제공합니다. 

- **타겟 유저:** 당장 영어 결과물이 필요하지만 장기적으로 진짜 작문 실력을 키우고 싶은 직장인 및 취업 준비생 
- **주요 가치:** '시작의 두려움' 극복 + 과거 오답 DB를 반영한 1:1 초개인화 피드백

## 2. 핵심 기능
- 🧩 **Zero-Prompt 기반 인터랙티브 조립 UI**
  - 파편화된 키워드나 문장을 입력시 AI가 의미론적 구문(Chunk) 단위로 분해하여 조립 칩을 제공.
- 📸 **손글씨 OCR 인식 지원(구현예정)**
  - 카메라 및 이미지 스캔을 통해 손으로 작성한 문장도 빠르게 디지털화 및 칩으로 변환.
- 🧑‍🏫 **초개인화된 문법 및 어순 튜터링**
  - 사용자가 칩을 올바르게 조립하기까지 시도한 '오답 횟수'를 DB에 기록하여, 다음 피드백에 반영.

## 3. 기술 스택
- **Client:** `C++`, `Qt (Qt Network)`
- **Server:** `Python`, `FastAPI`
- **AI / Vision:** `Gemini API`, `OpenCV`, `Tesseract OCR`
- **DB:** `MariaDB0` 
- **Analytics:** `Amplitude` (사용자 데이터 및 이벤트 수집)
- **Infra / CI:** `AWS EC2` (클라우드 환경 배포), `GitHub Actions` (Windows 크로스 컴파일 - `windeployqt` 활용)

## 4. 기술적 도전 및 아키텍처 최적화

### ⚡ 1. 통신 아키텍처 최적화 (State Hiding)
- **문제 인식:** '문장 분석'과 '최종 피드백'에 각각 통신이 발생하면 총 30초 이상의 대기 시간이 생겨 치명적인 UX 저하 예상.
- **해결 과정 (Why & How):** AI 서버가 '조립용 칩'과 '상세 피드백'을 한 번에 생성해 반환하도록 통신을 1회로 통합. 클라이언트(Qt)는 내려받은 피드백 항목을 즉시 렌더링하지 않고 메모리에 은닉(State Hiding) 시켜 두었다가, 사용자가 조립을 완료하는 즉시 통신 딜레이 없이 띄워 압도적인 속도감을 확보했습니다.

### 🛡️ 2. 비동기 통신 충돌(Race Condition) 방어 로직 설계
- **문제 인식:** 칩 조립 성공 메세지가 순식간에 사라지는 버그 발생. (Qt의 메인 이벤트 루프 충돌)
- **해결 과정:** 조립 성공 후 백그라운드로 전송되는 오답 횟수 기록(`update-retries`) API의 응답이 메인 API(QNetworkReply)를 덮어쓰고 재트리거하는 문제임을 파악. 핸들러 최상단에 `reply->request().url()` 라우팅 분기 처리를 구현하고, 백그라운드 응답은 철저히 무시 후 `.deleteLater()`를 호출하는 비동기 충돌 방어 로직을 작성했습니다.

### 💾 3. 의미 기반 DB 설계 및 부하 최적화
- **문제 인식:** 매 시도마다 텍스트 전체를 DB에 저장할 경우 발생하는 비효율성.
- **해결 과정:** 오답의 본질은 '어휘력'이 아닌 '어순 감각(Syntax)' 부족에 있음을 파악, 텍스트 대신 `assembly_retries`(상태 조립 오답 횟수)라는 정수형(INT) 컬럼만 추가하여 스토리지 부하를 최소화했습니다. 또한, FK와 `ON DELETE CASCADE`를 도입해 데이터 무결성을 유지하고 고아 데이터를 방지했습니다.

### 🧠 4. 프롬프트 엔지니어링 기반 UI/UX 제어
- **인지 과부하 통제:** LLM이 마침표나 쉼표 등 불필요한 단위까지 쪼개거나 텍스트를 너무 길게 뱉지 않게 하기 위해 제약을 걸었습니다. 
- 프롬프트 상단에 단일 문장(One single sentence) 강제, 3~7개의 의미론적 청킹(Semantic Chunks) 규칙을 엄격히 적용해 클라이언트 UI 레이아웃의 오버플로우나 붕괴를 원천 차단했습니다.

### 🚥 5. 분산 트래픽 제어 및 안정성
- 무분별한 API 요청으로 인한 서버/AI 토큰 남용을 방지하기 위해 `Limiter`와 `slowapi`를 적용해 1분당 최대 요청 5번으로 제한. 에러 메세지로 우회 처리하여 서버 다운사이징을 예방했습니다.

## 5. 향후 발전 방향 (Iteration)
